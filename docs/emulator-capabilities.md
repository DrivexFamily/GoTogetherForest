# 에뮬레이터 기능표 (외부 실측)

> 같이가숲이 이 표를 쓰는 방식: **되는 쪽으로 설계한다**(decisions.md 원칙 0). 아래 표에서 ✅인 것은 바로 쓰고, ❌인 것만 대체 방법을 찾거나 팀원과 다시 상의한다.
> 우리 앱의 적용 결과와 정확한 API는 `docs/sdk-capabilities.md`에 기록한다.
>

> | --- | --- |
> | 안전 km의 거리 | 총 주행거리(Odometer) 차이 ✅. 트립 거리는 ❌ |

- 출처: 외부 실측(확인용 앱, 2026-10-31). 팀원 지인이 같은 에뮬레이터에서 측정해 공유한 표를 블라인드 원칙에 맞게 옮겼다(이름·계정·경로 제외).
- 근거: Vehicle SDK 2.3.2 소스, Virtual Console `GET /vehicle/catalog`, Playground Maven 저장소, Playground 웹 콘솔, 에뮬레이터 실측(Pleos Connect v2.1.0, Android 14 / API 34)
- 실측 방법: 공모전 앱과 따로 설치한 확인용 앱으로 SDK 함수를 리플렉션으로 전부 호출하고, Virtual Console 값을 하나씩 바꿔 앱에 알림이 오는지, 앱에서 쓰기를 했을 때 콘솔에 반영되는지 봤다.
- 목적: 아이디어를 짤 때 "이 기능이 지금 환경에서 구현·시연 가능한가"를 바로 찾아보기 위한 표
- 표기: ✅ 실측 성공 · ⚠️ 조건부·이상 동작 · ❌ 안 됨 · — 해당 없음

> 2차 PT는 **실차 없이 에뮬레이터로만** 진행한다(설명회 10/28). 그래서 "SDK에 함수가 있다"보다 **"에뮬레이터에서 실제로 되고, Virtual Console로 값을 바꿔 시연할 수 있다"** 가 중요하다.

### 공통 주의점 (코드 짤 때)

1. **영역(Area)을 정확히 맞춰야 한다.** 공조·무드등·문 잠금은 "운전석 하나"로 부르면 실패하고 **여러 자리를 묶은 영역**으로 불러야 한다. 어떤 영역을 쓰는지는 `checkXxxCapabilities`로 먼저 조회한다.
2. Virtual Console 쓰기는 대부분 **정수만** 받는다 (소수 → HTTP 400).
3. 일부 값은 콘솔과 **부호·단위·참거짓이 다르다** (핸들 각도, 창문, 배터리, 좌석 착석).
4. "성공" 응답이 와도 실제로 안 바뀌는 쓰기가 있다 (상향등, 무드등 켜기, 충전 한도). 쓰기 후에는 읽어서 확인한다.

## 3. 위치·내비

| 기능 | 실측 |
|---|---|
| NaviHelper 연결 | ✅ |
| 현재 위치 (`getCurrentLocationInfo`) | ✅ 위도·경도·주소 (예: 37.41, 127.09 "수정구 시흥동") |
| 경로 상태 (`getRouteStateInfo`) | ✅ 경로 안내 중 여부, 경로 옵션, 교통 정보 |
| 즐겨찾기·최근 목적지 | ✅ (비어 있음) |

| 목적지 설정·경로 요청 | 미시험 (설명회 예시: 장소 추천 → 목적지로 설정) |
| FusedLocation | ⚠️ `isSupported=true`, 연결됨. 하지만 30초 동안 위치가 앱에 오지 않음. 서비스 로그에는 미국 기본 위치(구글 본사)만 보임 → **위치는 NaviHelper로 받는 것을 권장** |
| 위치로 속도 계산 | FusedLocation 데이터에 속도 항목이 없음. NaviHelper 위치를 시간 간격으로 비교하는 방법은 미시험 |

## 4. 음성 (TTS·STT)

| 시험 | 결과 |
|---|---|
| TTS `ON_DEVICE` (에뮬레이터 안 음성 엔진, 열쇠 불필요) | ✅ **소리 남** — 음성 합성 후 오디오 재생(`play!`)까지 확인 |
| TTS `SERVER` (열쇠 없이) | ❌ 준비(onReady) 후 `onError UNKNOWN` — 열쇠 등록(`registerApp`)이 필요한 것으로 보임, 열쇠로는 아직 미시험 |
| TTS `HYBRID` (열쇠 없이) | ⚠️ 시작(onStart)까지 됨, 소리 확인 전 다음 시험으로 넘어감 |
| STT `ON_DEVICE` | ⚠️ 준비(onReady)·인식 시작까지 됨. 에뮬레이터 마이크 입력이 없어 인식 결과는 미확인 |

TTS 쓸 때 주의
- 리스너(`addEventListener`)는 `initialize` **성공 뒤에** 붙인다. 먼저 붙이면 SDK 내부 예외(`lateinit property tts`)
- `setAudioAttributes`로 소리 종류를 지정한다 (예: `USAGE_ASSISTANCE_NAVIGATION_GUIDANCE`)
- 처음에 에뮬레이터 음성 서비스가 `audioTrack is null`로 소리를 못 냈다. `adb shell am force-stop ai.pleos.playground.caas`로 서비스를 다시 시작하자 해결 → **시연 전에 한 번 소리 확인 필요**
- TTS 의존성을 넣으면 앱 크기가 최대 약 5MB 늘어난다 (universal-access 포함)

## 8. 1회 주행 거리 구하기 (외부 실측, 2026-11-02)

트립 주행 거리·시간(`getTripCumulativeDrivingDistance` 등)은 에뮬레이터에서 지원하지 않는다. 총 주행거리(`Odometer.getCurrentDistanceDriven`, km, Float, 1m 단위까지 옴, 권한 `CAR_DRIVE`)를 **출발 때와 도착 때 적어 두고 빼서** 구한다. 계기판의 트립 미터를 앱이 직접 만드는 방식이다.

```
출발(기어 D): 총 주행거리 1234.500 km 기록, 시각 기록(SystemClock.elapsedRealtime)
주행 중   : 총 주행거리가 바뀔 때마다 최신 값 저장
도착(기어 P): 1235.300 km → 1회 주행 거리 0.8 km, 시간 = 도착 − 출발
```

주의할 점(외부 실측 메모)
- 앱이 출발 순간을 봐야 한다. 이미 D인 상태에서 켜면 그 순간을 출발로 삼는다.
- 구독을 화면이 보일 때만(onStart~onStop) 하면, 다른 앱이 가릴 때 기록이 빠진다.
- 값이 음수가 되지 않게 0 이상으로 자른다.
- Float(km)라 총 주행거리가 큰 차(수십만 km)에서는 수십 m 오차가 날 수 있다. 성적 계산에는 충분하다.
- 앱이 꺼지면 기록이 사라지므로 출발 값과 시각을 저장해 둔다.
- Virtual Console: 슬라이더는 1km 단위, HTTP `PUT /vehicle/odometer?traveled_distance_km=1.25`는 소수 km 가능. 줄일 수 없다(400). HTTP로 쓸 때는 `POST /browser/session?client=x`를 1~2초마다 보내야 한다(없으면 `emulator_inactive`/503).
- **주의(2026-11-02 Mac 실측, §10-2):** 이 PUT은 "N km 더하기"가 아니라 **"총 N km로 맞추기"**다. 그리고 차속이 있어도 주행거리는 저절로 늘지 않는다. 그래서 1회 주행 거리를 시험하려면 출발 뒤에 총 주행거리를 직접 더 큰 값으로 써야 한다.

같이가숲 적용
- 결정 #5대로 이미 이 방식이다(`core:trip` SafeDistanceMeter). 같이가숲의 "여행"은 기어 D→P 한 번이 아니라 **출발부터 목적지 도착까지**이고, 휴게소 정차(P)를 지나도 이어진다.
- 보완함(커밋은 메인, 2026-11-02): 실차 여행 중(주행 중·정차 중)이면 백그라운드에서도 신호를 계속 받는다. 여행 상태(tripId, 출발 주행거리·시각, 진행률 최고값, 안전 km 요약, 이미 낸 음성)를 저장해 앱이 꺼져도 다시 켜면 이어 간다(꺼져 있던 동안의 거리는 "판정 못 한 km", 12시간 지나면 버림). 이미 D로 달리는 중에 켜면 그 순간이 출발이다. 차이는 Double로 계산하고 음수는 0으로 자른다. 자세한 설명: `docs/architecture.md` 11-11, 14-13.

## 9. 에뮬레이터 왼쪽 안내의 경고 (Mac 담당 세션 실측, 2026-11-02)

시연 화면 왼쪽에 "도어 열림", "프렁크를 닫으세요", "안전 벨트를 매세요."가 뜬다. 우리 앱이 아니라 에뮬레이터 시스템 앱(`ai.umos.drivingview`)의 주행 전 안내다.

- **동작:** 기어가 P가 될 때마다 안내가 처음부터 다시 돈다(프렁크 → 문 → 벨트). 조건을 채운 단계는 건너뛰고, 기어 D에서 차속이 0보다 크면 끝난다.
- **문·프렁크가 열린 것으로 나온 이유:** `/vehicle/state`에는 문이 닫힘(false)으로 보여도, 한 번도 쓰인 적이 없으면 에뮬레이터 차량 쪽은 열린 상태로 안다.

| 경고 | 끄는 방법 | 결과 |
| --- | --- | --- |
| 도어 열림, 프렁크를 닫으세요 | `PUT /vehicle/body?door_fl=0&door_fr=0&door_rl=0&door_rr=0&frunk=0&trunk=0` (창문도 `&window_fl=0…`) | ✅ 바로 사라짐 |
| 안전 벨트를 매세요. | telltale `SeatBelt` Off, 좌석 착석 `seat?kind=occupied` 모두 시도 | ❌ 안 사라짐. Virtual Console에 벨트 체결 항목이 없고, `cmd car_service`로 직접 쓰기는 막혀 있음(user 빌드) |

- 우리 쪽 적용: `tools/mac/stage.sh`(녹화 전 준비)와 점검 스크립트가 시작할 때 문을 닫는다(`check-common.sh` `vc_close_body`).
- 한 번 닫은 프렁크가 나중에 다시 열림으로 돌아온 적이 있다(§10-3). 녹화 직전마다 `stage.sh`를 다시 돌린다.
- 벨트 안내는 P 장면(출발 전·휴게소·도착)에만 보인다. 영상은 오른쪽 앱 영역만 잘라 쓰거나 자막으로 설명한다.
- 참고: 이 시스템 앱은 초당 약 50장을 계속 그린다(로그 `DrivingView FPS: 49.9`). uiautomator가 느린 원인으로 본다(`docs/sdk-capabilities.md` 11-4).

## 10. 주행 제한·주행거리·프렁크 (Mac 담당 세션 실측, 2026-11-02)

Pleos Connect v2.1.0 에뮬레이터(Mac arm64)에서 `tools/mac/stage.sh`, 점검 스크립트, Virtual Console HTTP API를 돌리며 확인했다. 같은 날 앱 재검증 결과는 `docs/sdk-capabilities.md` 11-5.

### 10-1. 주행 규제 강제 명령이 없다

- `adb shell cmd hmg_car_service --service drivingstate driving_regulation off` → `cmd: Can't find service: hmg_car_service`. 이 에뮬레이터에는 그 서비스가 없다. `docs/pleos-dev-guide.md`·`CLAUDE.md`에 적힌 명령은 이 버전에서 쓸 수 없다.
- 주행 제한은 **기어로만** 바뀐다: 기어 D → `CarUxRestrictions` 활성 비트 80(`NO_SETUP` 64 + `NO_VIDEO` 16), 기어 P → 0.
- 시험 방법: Virtual Console(브라우저 또는 HTTP `PUT /vehicle/gear?gear=Drive|Park`)로 기어를 바꾼다.
- 서비스가 있는지 확인: `adb shell service check hmg_car_service`(없으면 `Service hmg_car_service: not found`가 나올 것으로 예상, Mac에서 이 명령 자체는 아직 안 돌려 봄) 또는 `bash tools/mac/emulator.sh drive-check`(끝 코드 3 = 없음).
- 우리 쪽 적용: `emulator.sh drive-on/drive-off`는 서비스가 없으면 "기어 D/P로 시험" 안내만 하고 0으로 끝난다. `stage.sh` 4단계는 "(이 에뮬레이터에는 없음)" 한 줄만 내고 넘어간다.

### 10-2. 총 주행거리(Odometer) HTTP API

| 확인 | 결과 |
| --- | --- |
| `PUT /vehicle/odometer?traveled_distance_km=N`의 뜻 | **총 N km로 맞추기**(더하기 아님). 331701에서 N=331703을 쓰면 331703이 된다 |
| 차속 30km/h로 몇 분 주행 | 주행거리가 **저절로 늘지 않음** |
| 소수 값 | 331706.8을 쓰면 `/vehicle/state`에는 331706.8125(float32)로 들어가고, 앱은 331706.8로 읽음 |
| 줄이기 | 안 됨(400, §8) |

- 1회 주행 거리(§8)를 시험하려면 출발(기어 D) 뒤에 총 주행거리를 지금 값보다 큰 값으로 직접 써야 한다. 예: 지금 331701이면 `traveled_distance_km=331703` → 2km.
- float32라 총 주행거리가 수십만 km면 약 0.03km(31m) 간격으로만 저장된다(예: 331706.8 → 331706.8125, 12.5m 차이). 그래서 1회 주행 거리에 수십 m 오차가 날 수 있다(§8 주의점과 같음). 안전 km 판정에는 충분하다.

### 10-3. 닫았던 프렁크가 다시 열림으로 돌아옴

- 예전에 `vc_close_body`로 닫았던 프렁크(`frunk`)가 나중에 다시 `true`(열림)로 돌아가 있었다. 원인은 모른다(`pm clear` 뒤이거나 기어 P를 여러 번 오간 뒤일 수 있음).
- `stage.sh`로 다시 닫으면 사라진다. 그래서 녹화 직전마다 `stage.sh`를 돌린다.

### 10-4. 화면 읽기(uiautomator)가 왼쪽 시스템 창만 읽을 때

- `uiautomator dump`가 가끔 왼쪽 시스템 창(`ai.umos.drivingview`)만 읽고 우리 앱 노드는 0개다. 예: 도착 축하 화면에서 drivingview 노드 20개, 앱 노드 0개.
- 앱 영역을 한 번 누르니(`input tap`) 다시 앱을 읽었다. dump는 "지금 활성 창" 하나만 읽는 것으로 보인다.
- 우리 쪽 적용: `tools/mac/check-common.sh`의 `refresh_ui`가 이 경우를 알아채면, 앱이 맨 앞일 때만 앱 창 위쪽 여백(버튼 없는 곳)을 한 번 누르고 한 번만 다시 읽는다. report에 "[화면 다시 읽기]"로 남는다.

## 11. 네트워크·음성 엔진·앱 데이터 (Mac 담당 세션 실측, 2026-11-02)

- **비행기 모드:** Virtual Console 쓰기는 200으로 답하지만, 차량 신호(기어, 차속, 주행 제한)는 바뀌지 않습니다. 차량 신호가 에뮬레이터 안 네트워크를 거치는 것으로 보입니다. 이때 같이가숲은 "전부 데모"(데모가 차속·기어까지 만듦)로 도착까지 동작했습니다.
- **음성 엔진(ON_DEVICE):** 비행기 모드에서도 끝까지 말했습니다. 하지만 가끔 `ON_DEVICE_ENGINE_ERROR` 상태에 빠지고, 앱이 엔진을 새로 초기화해도 풀리지 않습니다. `adb shell am force-stop ai.pleos.playground.caas` 뒤에는 다음 요청부터 말합니다. 그래서 `try.sh`와 `stage.sh`가 이 명령을 실행합니다.
- **음성 서비스를 끄면**(`pm disable-user`): 앱은 바로 "쓸 수 없음 – 초기화 실패(UNKNOWN)"를 받습니다. 화면 흐름은 그대로입니다.
- **내비 서비스를 끄면**: NaviHelper가 `IllegalStateException`을 냅니다. 내장 지도 앱도 같은 이유로 죽었다가 다시 뜹니다.
- **앱 데이터 직접 보기:** 앱이 AAOS 사용자 10에만 설치되어 `run-as`로 파일을 읽을 수 없습니다(`run-as --user`도 지원 안 함).
- **창 크기:** `wm size`는 화면만 바꾸고 앱 창은 그대로입니다. 앱 창 크기는 `am task resize <task> 853 90 <853+너비> 1300`(160dpi라 px = dp)으로 바꿀 수 있습니다.
- **가려진 앱 얼리기:** 다른 앱이 화면을 가리고 약 10~19초가 지나면(11-02 약 19초, 11-05 약 10초) ActivityManager가 앱 프로세스를 얼린다(`am_freeze`, cached app freezer). 얼린 동안은 코드가 돌지 않고, 돌아올 때 프로세스가 다시 시작될 수 있다. 계속 돌려면 포그라운드 서비스가 필요하다.
- **화면 읽기:** `adb shell uiautomator dump --windows /sdcard/x.xml`이 된다. 모든 창(우리 앱, 왼쪽 차량 창, 시스템 막대)을 한 번에 읽는다.
- **우리 앱 창 위치:** `frame=[853,90,2535,1300]`(2560×1440, 160dpi). 왼쪽 차량 창은 `[0,0,853,1300]`이다.
