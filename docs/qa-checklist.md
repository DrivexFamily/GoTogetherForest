### M0. 공통 준비 (저장소 폴더에서, **bash** 터미널 하나에서 이어서)

`tools/mac/check-common.sh`는 bash용이라 zsh라면 먼저 `bash`를 입력합니다.

```bash
export PATH="${ANDROID_HOME:-$HOME/Library/Android/sdk}/platform-tools:$PATH"
export ADB=adb VC=http://127.0.0.1:8088 VC_CLIENT=ggf-qa W=0 H=0
export APP_ID="$(awk -F= '$1=="app.applicationId"{gsub(/[ \t\r]/,"",$2);print $2}' gradle.properties)"
export ACT=app.familyjourney.MainActivity
export OUT="$PWD/captures/verification/qa/ggf-qa-$(date +%m%d-%H%M)"   # 저장소 폴더 기준, git에 올라가지 않음
export REPORT="$OUT/report.txt"
mkdir -p "$OUT"
note() { printf '%s %s\n' "$(date '+%H:%M:%S')" "$*" | tee -a "$REPORT"; }
. tools/mac/check-common.sh                      # vc_connect, vc_put, vc_disconnect, now_ms
U="$(adb shell am get-current-user | tr -dc '0-9')"; note "현재 사용자 $U"
NIGHT0="$(adb shell cmd uimode night | awk '{print $NF}' | tr -d '\r')"; note "원래 야간 모드 $NIGHT0"
cap() { adb exec-out screencap -p > "$OUT/$1.png"; note "사진 $1"; }
burst() { for i in 1 2 3 4 5 6; do adb exec-out screencap -p > "$OUT/$1-$i-$(now_ms).png"; sleep 0.3; done; }
# v2.1.0 에뮬레이터에는 hmg_car_service가 없다(2026-11-02 실측). 그래서 기어로 주행 제한을 켜고 끈다(D: bits=80, P: 0)
reg() { note "주행 규제 $1 ($(now_ms))"; if [ "$1" = on ]; then vc_put "/vehicle/gear?gear=Drive"; vc_put "/vehicle/controls?speed=30&accelerator=0&brake=0"; else vc_put "/vehicle/controls?speed=0&accelerator=0&brake=0"; vc_put "/vehicle/gear?gear=Park"; fi; }
adb logcat -c
vc_connect || note "Virtual Console 연결 실패(쓰기 503이면 1분 뒤 다시)"
vc_put "/vehicle/controls?speed=0&accelerator=0&brake=0"; vc_put "/vehicle/gear?gear=Park"
reg off
adb shell pm grant --user "$U" "$APP_ID" android.car.permission.CAR_SPEED
adb shell am start --user "$U" -n "$APP_ID/$ACT"
```

- 아이 프로필이 없으면 첫 실행 화면에서 보호자 확인과 아이 하나를 만들어 둡니다(별명은 실명이 아닌 것).

### M1. 주행 규제 on/off 반응 (점검표 1-2, 1-9, 10-10)

1. 홈(기어 P, 규제 off)에서 `cap m1-1-home`. 기대: "데모로 해 보기"·"숲 보기" 버튼이 보인다.
2. `reg on; burst m1-2-on`. 기대: 1초 안에 홈 → 진행 화면, 홈 버튼 줄 없음. 사진 이름의 시각(ms)과 `reg on` 시각의 차이를 적는다.
3. 진행 화면에서 `cap m1-3-driving`, 4초 뒤 `cap m1-3-driving-b`. 기대: 문구 한 줄과 "크게/작게"만, "소리 끄기"·"데모로 해 보기" 없음, 두 사진의 앱 영역이 같음.
4. `adb shell input keyevent KEYCODE_BACK; sleep 1; adb shell dumpsys activity activities | grep -E "topResumedActivity|ResumedActivity" > "$OUT/m1-4-back.txt"`. 기대: 앱이 끝나지 않고 뒤로 감(같은 앱이 위에 없음). `adb shell am start --user "$U" -n "$APP_ID/$ACT"`로 다시 열면 진행 화면 그대로.
5. `reg off; burst m1-5-off`. 기대: 1초 안에 정차 모습("소리 끄기" 보임). "데모로 해 보기"를 눌러 데모 시작 → "데모 주행" 배지 → 발표자 패널 펼치기 가능. "소리 끄기"를 누르고 데모 진행 중 안내 음성이 나오지 않는지 `adb logcat -d -s GgfApp | tail -20 > "$OUT/m1-5-mute.txt"`로 본다("음소거라 말하지 않음").
6. 데모가 켜지고 기어 P인 상태에서 `reg on; burst m1-6-demo-on`. 기대(실제 제한 우선): 데모 장면과 상관없이 주행 화면 규칙(발표자 패널 접힘, 펼치기 없음, 정지 그림).
7. `reg off`, `vc_put "/vehicle/gear?gear=Drive"`(차속 0) → `cap m1-7-unrestricted-D`. 기대: 움직임은 되지만 새싹 수·"데모로 해 보기"·숲 버튼은 없음(기어 P가 아님).
8. M-끝.

### M2. 세로·가로 (점검표 7-1, 7-10)

1. Host Display Bridge 폴더에서 `go run . --avd "<AVD 이름>"`(포트 8095/8096 비어 있어야 함). 에뮬레이터의 FormFactorConsole 앱 → preset "12.9인치 Portrait" → "가상 디스플레이 생성".
2. 디스플레이 번호 확인: `adb shell dumpsys display | grep -E "mDisplayId=|mBaseDisplayInfo" > "$OUT/m2-displays.txt"`. 새 디스플레이 번호를 `D`로 둔다.
3. `adb shell am start --user "$U" --display "$D" -n "$APP_ID/$ACT"` → 홈 사진: `adb shell dumpsys SurfaceFlinger --display-id`로 물리 id를 보고 `adb exec-out screencap -d <물리 id> -p > "$OUT/m2-3-portrait-home.png"`.
4. 같은 디스플레이에서 데모 시작 → `reg on` → 진행 화면 사진(m2-4), `reg off` + 휴게소(P) 사진(m2-5), 도착 결과·숲 사진(m2-6). 기대: 잘림·겹침·레터박스 없음, 큰 % 숫자와 한 줄 문장이 모두 보임.
5. preset "14.6인치 Landscape"로 바꿔 3~4를 다시(사진 이름 `landscape`).
6. 데모 진행 중(예: 40%)에 preset을 세로 ↔ 가로로 바꾼다. 기대: 같은 진행률·같은 화면이 이어진다(되감기 없음).
7. Host Display Bridge가 안 되면 대신 `adb shell wm size 1440x2560`(세로처럼) → 사진 → `adb shell wm size reset`. 이때는 결과에 "wm size로 대신함"을 적는다.
8. M-끝.

### M3. 1:1·2:1 창 (점검표 7-2)

1. 내비(내장 지도) 앱을 열고, 같이가숲을 앱 영역 반쪽에 띄워 1:1로 만든다(런처의 분할 방법). 2:1·1:2가 되는 화면이면 그것도 만든다.
2. 창 크기 기록: `adb shell dumpsys activity activities | grep -E "mBounds|$APP_ID" > "$OUT/m3-bounds.txt"; adb shell wm density >> "$OUT/m3-bounds.txt"`. 창 너비(dp) = px ÷ (density ÷ 160).
3. 1:1에서 데모 시작 → 진행 화면(`reg on`) 사진 m3-3, 휴게소(`reg off` + P) 사진 m3-4, 도착 축하 사진 m3-5.
4. 기대: 600dp 미만이면 "큰 % + 길 + 한 줄"만(짧은 문장 "끝말잇기 4판 남았어요"처럼), 600~840dp면 그림 + 보조 줄 + 버튼. 잘림·겹침·레터박스 없음.
5. 분할이 안 되면 "분할 방법 모름"으로 적고 M2의 wm size 방법으로 너비만 바꿔 본다(`adb shell wm size 1100x1440` → 사진 → `wm size reset`).
6. M-끝.

### M4. 라이트·다크 (점검표 7-3)

1. 지금 값 기록: `adb shell cmd uimode night > "$OUT/m4-before.txt"`.
2. `adb shell cmd uimode night yes; sleep 2` → 홈 사진 m4-2, 데모 시작 → 진행 화면(`reg on`) m4-3, 휴게소(`reg off`) m4-4, 숲 m4-5, 도착 결과 m4-6.
3. 다크 상태에서 앱을 처음부터 켜며 깜빡임 확인: `adb shell am force-stop --user "$U" "$APP_ID"; adb shell am start --user "$U" -n "$APP_ID/$ACT"; burst m4-7-cold`. 기대: 흰 화면이 번쩍이지 않음.
4. `adb shell cmd uimode night no` → 같은 화면 사진(이름 `light`). 기대: 두 테마 모두 글자가 바탕과 잘 구분되고, 앱이 다시 시작되지 않음(진행률 유지).
5. `uimode`가 차 화면에 반영되지 않으면 그 사실과 차량 설정의 주간/야간 메뉴 유무를 적는다.
6. M-끝(야간 모드는 M0에서 적어 둔 원래 값으로 돌아간다).

### M5. 네트워크 끊김 (점검표 6-7)

1. `adb shell cmd connectivity airplane-mode enable; adb shell svc wifi disable; adb shell svc data disable; sleep 3`
2. 확인: `adb shell ping -c 1 -W 2 8.8.8.8 > "$OUT/m5-ping.txt" 2>&1`. 기대: 실패(끊김).
3. `adb logcat -c; adb shell am force-stop --user "$U" "$APP_ID"; adb shell am start -W --user "$U" -n "$APP_ID/$ACT" > "$OUT/m5-start.txt"`. 기대: 10초 안에 실행.
4. 홈 → "데모로 해 보기" → 출발 음성 → (발표자 패널) 도착 직전으로 → 도착 → P → 결과 화면까지. 사진 m5-4-*(진행·도착·결과).
5. `adb logcat -d -s GgfApp GgfVoice > "$OUT/m5-voice.txt"`. 기대: `"출발! 같이 가 볼까?": 말함(끝까지)`(ON_DEVICE라 네트워크 없이도), 앱이 죽지 않음, 숲에 새싹이 쌓임.
6. M-끝(네트워크 되살리기 포함).

### M6. TTS 없음 (점검표 6-6)

1. 음성 서비스 끄기: `adb shell pm disable-user --user 0 ai.pleos.playground.caas; adb shell pm disable-user --user "$U" ai.pleos.playground.caas; adb shell am force-stop ai.pleos.playground.caas`. 결과를 `"$OUT/m6-disable.txt"`에 남긴다.
2. 1이 막히면("cannot" 등) 대신 권한 빼기: `adb shell pm revoke --user "$U" "$APP_ID" pleos.car.permission.TTS_SERVICE`. 이것도 막히면 "TTS 없음 흉내 불가"로 적고 3으로 간다.
3. `adb logcat -c`, 앱 다시 시작 → 데모 시작 → 출발 → 크게/작게를 몇 번 누른다(반응이 늦지 않은지) → 도착 → P.
4. `adb logcat -d -s GgfApp GgfVoice > "$OUT/m6-voice.txt"`. 기대: `음성 "…": 쓸 수 없음 – …`(10초 안), 화면 문구는 그대로, 앱이 멈추거나 죽지 않음. 신호 확인(개발용) → "음성 시험" 결과 줄 사진 m6-4.
5. M-끝(서비스 켜기). 2를 했으면 `adb shell pm grant --user "$U" "$APP_ID" pleos.car.permission.TTS_SERVICE`(안 되면 `./gradlew installDebug`로 다시 설치).

### M7. 내비 경로 없음 (점검표 2-7, 6-3, 6-4)

1. 데모가 꺼진 실차 상태(개발 메뉴 "데모 끄기 (실차로)")이고 내비 안내가 없는지 확인. 홈 → "이렇게 출발해요" → 진행 화면 사진 m7-1. 기대: "내비에 목적지를 설정해 주세요", "목적지를 정하면 여기서 진행률을 보여 줘요", "데모로 해 보기".
2. 주행: `vc_put "/vehicle/gear?gear=Drive"; vc_put "/vehicle/controls?speed=30&accelerator=0&brake=0"; reg on`, 3초 뒤 사진 m7-2. 기대: "목적지를 기다리고 있어요" 한 줄, 버튼 없음. (차속은 1초에 약 6km/h씩 줄어드니 사진 직전에 speed를 한 번 더 써도 됨)
3. 정차: `vc_put "/vehicle/controls?speed=0&accelerator=0&brake=0"; vc_put "/vehicle/gear?gear=Park"; reg off`, 사진 m7-3. 기대: 다시 "내비에 목적지를 설정해 주세요".
4. P 그대로 2분 10초 기다린 뒤 사진 m7-4. 기대: 경로 없는 여행이 끝나 "도착했어요!"와 "운전해 줘서 고마워요", 앱이 죽지 않음.
5. (선택, NaviHelper 연결 실패) `adb shell pm disable-user --user 0 ai.pleos.playground.service.navi; adb shell pm disable-user --user "$U" ai.pleos.playground.service.navi; adb shell am force-stop ai.pleos.playground.service.navi` → 앱 다시 시작 → 70초 기다림 → 신호 확인(개발용) 사진 m7-5. 기대: "Pleos NaviHelper" 실패 표시, 진행 화면은 1과 같음, 앱이 죽지 않음. 막히면 "흉내 불가"로 적는다.
6. M-끝(내비 서비스 켜기 포함).

### M8. (선택) 계정 파일에 별명 평문 없음 (점검표 9-4)

1. 아이 별명을 하나 정해 둔다(예: 실명이 아닌 "콩이").
2. `adb shell run-as --user "$U" "$APP_ID" ls -R files > "$OUT/m8-files.txt"`(안 되면 `--user "$U"` 없이).
3. `adb exec-out run-as --user "$U" "$APP_ID" cat files/datastore/account.preferences_pb | strings > "$OUT/m8-account.txt"`, 같은 방법으로 실차 여행 중(주행·정차)에 `files/datastore/trip.preferences_pb`도(`m8-trip.txt`, 여행 중이 아니면 파일이 비어 있거나 없음).
4. `grep -c "콩이" "$OUT"/m8-*.txt`. 기대: 0. 별명은 `g1:`로 시작하는 암호문으로만 보이고, trip 파일에는 좌표·별명이 없다.

### M9. (선택) 한쪽 기능만 켠 빌드 (점검표 5-7, 5-8)

1. 숲만: `./gradlew installDebug -Pfeature.journey.enabled=false` → `adb shell pm clear --user "$U" "$APP_ID"` → 실행 → 보호자 확인·아이 → 홈 "개발 메뉴" → "전부 데모로 해 보기"(숲만 켠 빌드에는 발표자 패널이 없고, 섞기 데모는 실제 차가 움직여야 흐르므로) → 아이의 숲 화면(데모가 주행 중이면 "차가 서면 숲을 볼 수 있어요" 정지 그림) → 약 3분 뒤 도착 결과가 저절로 뜸 → 숲. 사진 m9-1-*. 도착 결과 화면에 "데모 주행이라 포인트는 쌓이지 않아요"가 있어야 한다.
2. 진행 화면만: `./gradlew installDebug -Pfeature.forest.enabled=false` → 실행 → 홈 "출발"·"데모로 해 보기" → 진행 화면 → 도착 축하 + "홈으로". 사진 m9-2-*.
3. 두 경우 모두 `adb logcat -d | grep -E "FATAL|AndroidRuntime"`가 비어 있어야 한다.
4. 끝나면 기본 빌드로 되돌린다: `./gradlew installDebug`. 그다음 M-끝.
