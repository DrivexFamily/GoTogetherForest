지금까지 무엇을, 어떻게, 왜 했는지 정리한 안내서입니다. 앞으로 무엇을 할지도 담았습니다. 프로그래밍을 처음 배우는 대학교 1학년이 읽는다고 생각하고 썼습니다. 처음 나오는 낱말은 바로 뜻을 풀었고, 13장 용어 사전에도 모아 두었습니다. 이 안내서는 저장소에도 들어가므로, 블라인드 원칙에 따라 실명 대신 "팀원"이라고 적었습니다.

세 줄 요약

무엇을현대차 Pleos 공모전에 낼 차량용 앱 "같이가숲"을 만들고 있습니다. 아이에게 목적지까지 남은 길을 보여 주고, 아빠가 부드럽게 운전한 만큼 아이의 숲에 나무를 심어 주는 앱입니다.
어디서코드는 AI가 클라우드에서 씁니다. 그 코드는 GitHub에 올라갑니다. 팀원의 Mac은 그것을 내려받아 에뮬레이터라는 가짜 자동차 화면에서 실행합니다.
지금개발 환경이 모두 준비됐습니다. 앱이 가짜 차에서 기어·배터리·주행 제한 신호를 실제로 읽는 것까지 확인했습니다. 다음은 "주행 중에도 앱을 띄울 수 있는지(DO)"를 시험하는 단계입니다.
이 안내서를 읽는 법 1~4장은 개념과 전체 구조, 5~7장은 지금까지 한 일과 입력한 명령어, 8~10장은 코드·권한·AI 에이전트, 11장은 앞으로의 계획입니다. 시간이 없으면 0장, 3장, 9장, 11장만 읽어도 흐름을 잡을 수 있습니다.
정확성에 대해 사실은 공식 문서, 저장소의 기록(docs 폴더), 에뮬레이터에서 직접 본 결과로 확인했습니다. 아직 확인하지 못한 것에는 미확인이나 추정을 붙였습니다. 이 안내서는 작성 후 별도의 AI 검토자가 한 번 더 사실을 대조했습니다.

우리 앱: 같이가숲 (Go Together Forest)

🚗진행 화면 (주인공)

"아빠, 언제 도착해?"에 답합니다. 화면 속 길 위를 우리 차가 1%씩 달리고, "만화 두 편 보면 도착해요"처럼 아이 말로 남은 시간을 알려 줍니다.

🌳아이 계정의 숲

급가속·급정거 없이 부드럽게 달린 거리만큼 아이 숲에 새싹과 나무가 자랍니다. 전기차와 하이브리드는 보너스를 받습니다. 나무가 늘면 동물이 찾아옵니다.

🎁보호자 포인트

부드럽게 달린 1km마다 1포인트(1원)가 쌓입니다. 5,000P부터 현대차 혜택으로 바꾸는 것을 제안합니다. 이 교환은 제휴가 있어야 가능한 예시입니다.

가장 중요한 제약 하나운전 중에는 운전자의 눈을 끌면 안 됩니다. 그래서 주행 중에는 그림이 멈춰 있고 1%씩만 바뀌며, 애니메이션은 주차 중에만 나옵니다. 이 규칙을 지키려면 앱이 "지금 주행 중인가"를 정확히 알아야 합니다. 9장의 권한 이야기도 대부분 여기서 나옵니다.

결정의 전체 목록은 저장소의 docs/decisions.md에 있습니다. 그림으로 보려면 "같이가숲 개발 지도" 아티팩트를 보세요.

기초 개념 12가지

이 낱말들만 알면 나머지 장이 훨씬 쉬워집니다. 각 개념마다 일상에 빗댄 설명과, 우리 프로젝트에서 어디에 쓰이는지를 함께 적었습니다.

📱① 앱과 APK

안드로이드 앱은 APK라는 파일 하나로 묶여 설치됩니다. 압축 파일 안에 프로그램과 그림, 설정이 들어 있는 형태입니다.

비유 프로그램이 담긴 택배 상자. 열면 설치됩니다.

우리: 공모전에 Acorn_GoTogetherForest_release.apk를 냅니다.

🤖② Android, AAOS, Pleos Connect

Android는 휴대폰 운영체제입니다. 이것을 자동차용으로 바꾼 것이 AAOS(Android Automotive OS)입니다. 현대차그룹은 AAOS 위에 자기 기능을 더해 Pleos Connect라는 차량 운영체제를 만들었습니다.

비유 Android가 기본 건물이라면 AAOS는 자동차용으로 고친 건물이고, Pleos Connect는 현대차가 꾸민 인테리어입니다.

우리 앱은 Pleos Connect 위에서 돌아갑니다. 기획서 조사에 따르면 2026년 5월 그랜저에 처음 탑재됐습니다.

🖥️③ 에뮬레이터

컴퓨터 안에 만든 가짜 기기입니다. 진짜 자동차가 없어도 Mac 화면 안에서 Pleos Connect가 그대로 돌아갑니다.

비유 비행기 조종 시뮬레이터. 진짜 비행기 없이 조종을 연습합니다.

공모전 심사도 실차가 아니라 에뮬레이터로 합니다. 에뮬레이터는 그래픽 처리(GPU)가 필요해서 클라우드가 아니라 Mac에서 돌립니다.

💿④ 시스템 이미지와 AVD

시스템 이미지는 가짜 기기에 넣을 운영체제 원본(내려받기 약 4.7GB)입니다. AVD(Android Virtual Device)는 "이 이미지로, 이 화면 크기와 메모리로 가짜 기기를 만든다"는 설정 묶음입니다.

비유 시스템 이미지는 설치 CD, AVD는 그 CD로 조립한 컴퓨터 한 대.

우리: 이미지 pleos_car_emulator(API 34, arm64)로 AVD PleosConnect를 만들었습니다.

🧰⑤ SDK와 API

API는 다른 프로그램에게 일을 시키는 정해진 말투입니다. "지금 기어가 뭐야?"라고 묻는 함수 같은 것입니다. SDK는 그런 API와 도구를 한 상자에 담은 개발 도구 모음입니다.

비유 API는 식당 메뉴판, SDK는 메뉴판·주문서·안내서를 묶은 세트.

우리: Pleos Vehicle SDK(배터리·차종), NaviHelper(내비 남은 거리), Android 표준 CarPropertyManager(차속·기어)를 씁니다.

🔑⑥ 권한

앱이 민감한 정보(위치, 차속 등)를 읽으려면 권한이 필요합니다. 어떤 권한은 설치만 하면 자동으로 받고, 어떤 권한은 사용자가 "허용"을 눌러야 합니다.

비유 건물 출입증. 로비는 누구나 들어가지만, 서버실은 관리인의 서명이 필요합니다.

🧭⑧ 환경 변수와 PATH

터미널이 기억하는 "설정 메모"입니다. 예를 들어 JAVA_HOME은 "Java가 여기 있다"는 메모입니다. PATH는 "명령어 프로그램을 찾을 폴더 목록"입니다.

비유 전화번호부. brew를 부르면 터미널이 PATH라는 전화번호부에서 그 프로그램을 찾습니다.

🌿⑨ Git, GitHub, 커밋·푸시·풀

Git은 파일의 변경 기록을 사진처럼 찍어 남기는 도구입니다. 한 장의 기록이 커밋입니다. GitHub는 그 기록을 인터넷에 보관하는 곳입니다. 올리기는 푸시, 내려받기는 풀입니다. 브랜치는 작업용 갈래 길입니다.

비유 커밋은 세이브 파일, GitHub는 클라우드 세이브, 브랜치는 따로 진행하는 저장 슬롯.

우리 작업 브랜치: claude/lucid-babbage-a6quds. Sourcetree는 이 기록을 그림으로 보여 줍니다.

🏗️⑩ 빌드, Gradle, JDK

사람이 쓴 코드를 기기가 실행할 수 있는 APK로 만드는 과정이 빌드입니다. 빌드를 진행하는 도구가 Gradle이고, Gradle은 Java(JDK) 위에서 돌아갑니다.

비유 설계도(코드)를 공장(Gradle)에 넣으면 제품(APK)이 나옵니다. 공장 전기가 Java입니다.

4장

에뮬레이터와 웹(Virtual Console)은 어떻게 연결되나

"에뮬레이터랑 웹이랑 어떻게 연동되는지"라는 질문이 있었습니다. 브라우저에서 ACCEL을 누르면 에뮬레이터의 속도계가 올라갔는데, 그 사이에서 무슨 일이 일어나는지 그림으로 풀어 보겠습니다.

ACCEL을 누르면: 브라우저 → (adb가 이어 준 8088번 문) → Virtual Console 서버 → 가상 차량(VHAL)의 차속 값이 바뀜 → Car 서비스가 계기 화면과 우리 앱에 새 값을 전달. Virtual Console 서버가 VHAL 값을 바꾸는 내부 방식은 공식 문서에 자세히 나와 있지 않아, 이 그림의 가운데 부분은 구조를 단순화한 것입니다 추정 포함

꼭 기억할 세 가지

  • 127.0.0.1은 "내 컴퓨터 자신"이라는 뜻입니다. 인터넷 사이트가 아닙니다. adb가 Mac의 8088번 문을 에뮬레이터 안의 8088번 문에 이어 주기 때문에 브라우저로 에뮬레이터 안을 볼 수 있습니다.
  • Virtual Console은 "가짜 차의 페달과 기어"입니다. 진짜 차에서는 운전자가 페달을 밟지만, 에뮬레이터에서는 이 웹 화면이 그 역할을 합니다.
  • 우리 앱은 Virtual Console을 직접 보지 않습니다. 진짜 차와 똑같은 방법(Car 서비스, Pleos SDK)으로 값을 읽습니다. 그래서 에뮬레이터에서 되면 실차에서도 같은 코드로 동작할 가능성이 높습니다.
큰 발견우리 참고서(docs/pleos-dev-guide.md)에는 "Virtual Console로 차속은 흉내 낼 수 없다"고 정리돼 있었습니다. 그런데 지금 버전(v2.1.0)에는 ACCEL·BRAKE 페달이 있었고, ACCEL을 누르자 계기판 차속이 17km/h까지 올랐습니다. 그래서 시연 계획을 바꿨습니다. 다만 우리 앱이 이 차속을 읽는지는 아직 확인하지 못했습니다(차속 권한을 허용하기 전이라 "권한 없음"). 권한을 허용한 뒤 DO 시험 때 확인합니다. 급가속 판정 기능은 3단계에서 만듭니다. 잘 되면 PT에서 ACCEL을 세게 밟아 급가속 판정을 진짜 신호로 보여 줄 수 있습니다.

    Mac 개발 환경 설치 완료 문제 4개 해결

    무엇을
    설치 스크립트 setup.sh로 Sourcetree, Android Studio, Android SDK, Java 17, GitHub 도구를 설치하고, 저장소를 내려받고, 가짜 기기(AVD)를 만들었습니다. Pleos 시스템 이미지만은 Android Studio 화면에서 설치했습니다(아래 막힌 곳 4번). 설치된 것 전체는 6장에 있습니다.
    막힌 곳
    1. GitHub 로그인 코드: 브라우저에 터미널에 나온 8자리 일회용 코드(예: XXXX-XXXX)를 입력해 해결.
    2. 라이선스 거절: 긴 라이선스 끝의 Accept? (y/N)에 Enter만 눌러 "거절"로 처리됨 → yes | sdkmanager --licenses로 동의.
    3. brew: command not found: Homebrew 위치가 터미널 전화번호부(PATH)에 없었음 → ~/.zprofile에 등록.
    4. Pleos 이미지 못 찾음: Mac의 최신 도구는 명령줄 목록에 Pleos 이미지를 보여 주지 않음 → Android Studio 화면으로 설치하고, 스크립트를 "이미 설치된 폴더도 찾도록" 고침.
    왜
    한 번 만든 스크립트는 PT 현장 PC나 전시용 PC에서도 그대로 다시 쓸 수 있습니다. 손으로 하면 매번 빠뜨리는 것이 생깁니다.

권한 완전 정리

팀원 질문: "현대에서는 권한을 줄 생각인데, 우리가 괜히 권한을 못 받는다고 생각하는 것은 아닌지?"

결론부터아닙니다. 우리는 현대가 권한을 안 줄 거라고 가정하지 않았습니다. 에뮬레이터에서 본 "권한 없음"은 현대의 승인 문제가 아닙니다. Android가 원래 정해 둔 "사용자에게 한 번 허용받기" 단계를 아직 거치지 않았을 뿐입니다. 이 단계는 Android 규칙이라, 현대가 권한을 승인해도 보통 그대로 남습니다. 그래서 앱이 첫 실행 때 보호자에게 한 번 물어보도록 설계했습니다. 다만 플랫폼(현대)이 설치할 때 미리 허용해 주는 제도를 둘 수도 있어서, 그런 제도가 있는지 문의할 질문에 넣었습니다(아래 2번).

"권한"이라는 말이 서로 다른 세 가지를 가리켜서 헷갈리기 쉽습니다. 세 층으로 나눠 보겠습니다.

우리가 쓰는 권한 하나하나

자주 묻는 질문

에뮬레이터를 끄면 설정이 사라지나요?

아니요. AVD(가짜 기기)와 그 안에 설치한 앱은 남아 있습니다. 다만 우리는 매번 Cold boot(처음부터 부팅)를 하므로 켤 때 1~3분 정도 걸립니다.

Sourcetree에서 새 커밋이 안 보여요.

Sourcetree는 자동으로 새 기록을 가져오지 않을 수 있습니다. 상단의 "가져오기(Fetch)"를 누르면 GitHub의 새 기록이 보입니다. 내 폴더의 파일까지 바꾸려면 "당기기(Pull)"를 누릅니다. 터미널에서 bash tools/mac/sync.sh를 실행하면 가져오기(fetch)만 합니다. 파일까지 바꾸려면 git pull --ff-only를 씁니다.

Mac에서 코드를 직접 고쳐도 되나요?

되지만, AI도 같은 파일을 고치면 서로 부딪칠 수 있습니다. 지금은 코드는 AI가 쓰고, Mac은 "받아서 돌려 보는 곳"으로 쓰는 것이 가장 단순합니다. 고치고 싶은 것이 있으면 말로 알려 주세요.

클라우드 세션이 끝나면 작업이 사라지나요?

클라우드 컴퓨터 안의 파일은 사라집니다. 그래서 모든 결과를 GitHub에 커밋·푸시해 두었습니다. GitHub에 있는 것은 안전합니다.

AI가 내 Mac에서 직접 명령을 실행할 수 있게 하려면?

Claude 데스크톱 앱 → 설정 → Claude Code → Remote Control에서 숨김 폴더가 아닌 일반 폴더(예: ~/Projects)를 공유하면 됩니다. 그러면 에뮬레이터 켜기, 설치, 로그 수집을 AI가 대신 할 수 있습니다. 실행할 때마다 팀원 승인을 받습니다. 지금 등록된 폴더는 클라우드에서 쓸 수 없는 상태라 연결되지 않았습니다.

PT에서 기술 질문이 나오면 어떻게 대비하나요?

이 안내서의 3·4·8·9장과 docs/architecture.md가 기술 질문의 답입니다. "왜 이렇게 했나"는 docs/decisions.md에 있습니다. PT 전에 이 내용으로 질문·답변 연습 자료를 따로 만들 예정입니다.

스스로 점검하기

답을 생각해 본 뒤 눌러서 확인하세요. 다 맞히면 PT 기술 질문의 기초는 준비된 것입니다.

Q1. 에뮬레이터를 클라우드가 아니라 Mac에서 돌리는 이유는?

에뮬레이터는 GPU와 화면이 필요한데, 클라우드 컨테이너에는 둘 다 없기 때문입니다.

Q2. AI가 쓴 코드가 내 Mac까지 오는 길은?

클라우드에서 커밋 → GitHub에 푸시 → Mac에서 pull(또는 Sourcetree 당기기) → Mac에서 빌드 → adb로 에뮬레이터에 설치.

Q3. 브라우저 주소 127.0.0.1:8088은 어디인가?

내 Mac 자신의 8088번 문입니다. adb forward가 이 문을 에뮬레이터 안의 8088번 문(Virtual Console 서버)에 이어 줍니다.

Q4. 신호 확인 화면에서 차속만 "권한 없음"이었던 이유는?

CAR_SPEED는 Android에서 dangerous 등급이라 사용자가 "허용"을 눌러야 받기 때문입니다. 현대의 승인 문제가 아닙니다. 현대가 승인해도 보통 사용자 허용 단계는 남습니다.

Q5. 기어 권한(CAR_POWERTRAIN)은 왜 바로 됐나?

normal 등급이라 설치만으로 자동으로 받기 때문입니다.

Q6. 주행 중 앱이 가려진 것은 고장인가?

아닙니다. DO 표시가 없는 앱을 주행 중에 막는 플랫폼 규칙이 정상 동작한 것입니다.

Q7. 진행 화면과 숲 모듈이 서로를 모르게 만든 이유는?

한쪽만 켜도 앱이 동작하게 하려는 것입니다. 기능 분리와 안정성을 보여 줄 수 있습니다. 둘 다 core:trip의 이동 소식만 듣습니다.

Q8. "주행 제한을 모르면 true(제한 중)"로 둔 이유는?

정보가 없을 때 안전한 쪽을 택하려는 것입니다. 잘못해서 주행 중에 애니메이션이 켜지는 일을 막습니다.

Q9. 트립 거리를 못 읽는데 "안전 km"는 어떻게 계산하나?

차속에 시간을 곱해 계속 더하는 방법(적분)으로 거리를 직접 계산할 계획입니다. 급가속·급감속은 1초 동안의 차속 변화로 판정하고, 그런 일이 있었던 1km 구간만 뺍니다. 이 계산은 3단계에서 만듭니다.

Q10. Mac에서 빌드할 때 Java 17을 쓰는 이유는?

우리 빌드 조합은 Java 17 이상이 필요하고(Android 빌드 플러그인 AGP 8.8), Gradle 8.10.2는 Java 23까지만 지원합니다. 그래서 17~23 사이여야 합니다. Android Studio 내장 Java는 25라서 "25.0.4" 오류가 났습니다.
