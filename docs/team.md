## 2. 브랜치와 올리기

- 모두 작업 브랜치 `claude/lucid-babbage-a6quds` 하나에 올린다(팀원·Mac이 이 브랜치를 받아 확인한다). `main`에는 올리지 않는다. PR은 만들지 않는다.
- 올리기 전에 늘 `git pull --rebase origin claude/lucid-babbage-a6quds`. 충돌이 나면 상대 파일 주인의 변경을 지우지 않고 맞춘다. 모르겠으면 총괄 PM에게 묻는다.
- 작은 변경도 바로 커밋하고 올린다(묶어서 늦게 올리지 않는다).
- 커밋 메시지는 한국어. 실명·연락처·계정은 저장소 어디에도 쓰지 않는다(블라인드 원칙).

## 3. 검증과 알림 (팀원 지시, 2026-11-05)

- **검증은 팀원이 시킬 때만** 한다: 빌드 3종 테스트(`verify` 묶음), 전체 화면 캡처, Mac 에뮬레이터 확인. 그 사이에는 구현을 먼저 하고, 올리기 전에는 **컴파일만** 확인한다(예: `./gradlew -q :모듈:compileDebugKotlin`). 테스트 코드는 쓰되 돌리지 않는다.
- **변경마다 바로 알린다.** 올린 뒤 바로 총괄 PM에게 send_message: ① 무엇이 바뀌었나(한두 줄) ② 커밋 ③ 팀원이 직접 확인하는 방법(Mac에서 `bash ~/Projects/familyjourney/tools/mac/try.sh` → 어느 화면에서 무엇을 보면 되나) ④ 그림이 아직 없어 화면에 안 보이면 그렇다고. 총괄 PM이 팀원에게 전하고 현황판을 고친다.
- 문서만 바뀐 경우는 ③ 대신 파일 경로.
- 총괄 PM은 앱이 바뀐 변경을 팀원에게 알릴 때 Mac 세션에도 "[새 변경] 커밋 …"을 보내, 팀원이 에뮬레이터에서 바로 볼 수 있게 한다.
